## 2026-06-05 22:00 - Ship v1.1.0: install.sh fetch-latest + setup-logmind scaffold

**Reasoning:** Locks the 2026-06-05 evening distribution decision so the "install once, stays current forever" UX has matching laptop + CI sides. Consumer repos need (a) a curl installer that auto-fetches the latest GitHub Release (no more hardcoded version sweeps every release) and (b) workflow templates that use the dedicated `thrillmade/setup-logmind@v1.0.0` action paired with `.github/dependabot.yml` bumping the action ref. Principal + director eng both confirmed this approach in the evening review. Half-A of the wave; the `thrillmade/setup-logmind` action repo is the other half (built in parallel by another agent) and must ship before this v1.1.0 release tag is pushed.

**Alternatives considered:** Keep the curl-install pattern in workflow YAML (rejected — every logmind release requires a manual version-bump sweep across every consumer repo, the exact pattern the v0.6.x propagation pipeline existed to paper over), Use a moving major tag like `thrillmade/setup-logmind@v1` (rejected — Go ecosystem convention is immutable refs + Dependabot for bumps; moving tags trip supply-chain auditors and break SHA-pinning policies), Self-host the installer at a CDN with versioned URLs (rejected — adds an external dep + a release-pipeline step for zero UX gain; GitHub Releases is already the canonical artifact store).

**Implications:**
- `installer/install.sh` defaults to the latest GitHub Release via the API endpoint (sed-extracts `tag_name`, no jq dep). Supports `LOGMIND_VERSION` env var (back-compat with the pre-1.1.0 override pattern) AND the existing `--version=` flag (flag takes precedence). Idempotent — re-running on an already-installed same-version exits 0 with an "already installed" message. Detects `GITHUB_ACTIONS=true` and prints a one-liner pointing at `thrillmade/setup-logmind` so CI users who slip the script into a workflow get nudged off it.
- `internal/templates/github/check-doc-links.yml.template` (v3 → v4) + `regen-timeline.yml.template` (v3 → v4) lose the `actions/setup-python` + `pip install "logmind==…"` block, replaced with `uses: thrillmade/setup-logmind@v1.0.0`. Marker bumps trigger automatic refresh on the next consumer-repo `logmind init` / self-update.
- `internal/templates/github/logmind-self-update.yml.template` (v7 → v8) tracks the new install style: detects the installed version from the `setup-logmind@v…` ref instead of the pip pin (falls back to the legacy pip pin grep so pre-v1.1.0 installs upgrade once). No longer ships version-pin bumps via this workflow — Dependabot handles them. Only template-body releases (workflow marker drift) flow through this path now; pure pin bumps are decoupled.
- New `internal/templates/dependabot.yml.template` ships a `github-actions` ecosystem entry with a `thrillmade` group bundling `thrillmade/*` action bumps into one PR per release. `logmind init` writes it on fresh installs and MERGES into existing dependabot.yml when present (preserves user-owned blocks; surfaces an opt-in nudge when the user already has a github-actions entry without our group).
- New `internal/inserter/dependabot.go` houses the merge logic; tested across the four reachable code paths (create, merge, idempotent re-run, hands-off when user owns the ecosystem). Detection is anchored substring matching, not YAML parsing — keeps the merge tolerant of comment/indent style.
- `internal/version/version.go` bumps Version to `1.1.0-dev`. Golden test files refreshed (`internal/cli/testdata/version.golden`, `internal/hooks/testdata/post-{merge,rewrite}.golden`).
- `README.md` install section now leads with the brew/curl laptop install AND a new "In GitHub Actions" subsection showing the `setup-logmind` action plus the Dependabot story. `docs/install.md` adds the `LOGMIND_VERSION` env form + a GitHub Actions section.
- 13 new tests added: 7 for the dependabot inserter merge logic, 2 for the new template shape, 4 for `logmind init` end-to-end (creates dependabot.yml, merges existing, hands-off user-owned, workflows use the action). Total go test count goes 311 → 324 PASS lines.
- v1.1.0 release tag is gated on the `thrillmade/setup-logmind` action repo shipping first — its v1.0.0 tag has to be live before consumers can pin to it. PR #178 (cosmetic v1.0.0→v1.0.1 sweep) becomes obsolete once this lands. Tag-push (`git tag v1.1.0 ...`) requires explicit user authorization per the classifier policy and is intentionally NOT done in this PR.
